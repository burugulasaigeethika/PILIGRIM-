PilgrimAI — RAG Architecture Study Guide

Complete Technical Guide & Code Breakdown for Telangana Temples AI Assistant
100% Offline • Zero-Hallucination • Hybrid Search • Parent-Child RAG

1. Executive Summary & Core Philosophy

PilgrimAI is an offline, zero-hallucination domain AI assistant designed for pilgrims visiting temples across Telangana. It solves the critical limitations of standard RAG systems through four key pillars:

  • Parent-Child Chunking: Small 300-char child snippets for dense search precision + full parent section context for LLM comprehension.
  • Hybrid Retrieval: Combines Dense Vectors (semantic intent) and BM25 (exact Telugu terms, proper nouns, and prices) via Reciprocal Rank Fusion (RRF).
  • Neural Cross-Encoder Reranking: Re-evaluates top 30 candidates with deep cross-attention to pass the highest-scoring Top-3 parent chunks to the LLM.
  • Deterministic Inference (T=0.0): Guarantees responses strictly reflect dataset facts without hallucination.

2. High-Level Pipeline Flow

1
Query Planning (query_planner.py): Analyzes query, resolves aliases, and routes to 1 of 5 specialized retrieval routes.
2
Parallel Hybrid Search: Queries Qdrant (dense vectors) and BM25 (keywords) to fetch the top 30 candidate chunks.
3
Reciprocal Rank Fusion (rrf.py): Fuses and deduplicates rankings into a unified score.
4
Neural Reranking (reranker.py): Cross-Encoder evaluates query-chunk pairs and picks the top 3 parent passages.
5
Relevance Guardrail (guardrail.py): If top score < -3.0, returns an immediate polite refusal (saves LLM compute).
6
Context & Prompt Construction: Formats parent documents into clean Markdown with zero-hallucination rules.
7
LLM Generation & Grounding Check: Ollama Qwen 2.5 (1.5B) generates the answer, verified by answer_grounding_validator.py.

5. Top 5 Interview / Viva Questions & Answers

Q1: Why did you choose Parent-Child Chunking instead of standard fixed chunking?
Answer: Fixed chunking creates arbitrary cuts that often separate related data (like pooja ticket prices from pooja names). With Parent-Child Chunking, we search over small 300-character child chunks for high semantic precision, but inject the entire parent document into the prompt so the LLM has complete context.
Q2: Why combine Dense Vector Search and BM25 Sparse Search using RRF?
Answer: Dense vector embeddings understand high-level semantics (e.g., "where to stay" → accommodation), but can struggle with exact proper nouns and numbers. BM25 excels at exact keyword and numeric matching (e.g., "Saswatha Pooja ₹500"). Reciprocal Rank Fusion (RRF) merges their strengths without needing manual score tuning.
Q3: Why is Temperature set to 0.0 in the LLM?
Answer: PilgrimAI is an informative pilgrimage assistant where precision is vital. A temperature of 0.0 turns off stochastic creativity, ensuring the model deterministically selects the most probable tokens strictly grounded in the retrieved facts.
Q4: How does your pipeline block out-of-domain queries without wasting LLM tokens?
Answer: guardrail.py checks the top score from the neural Cross-Encoder. If the score is below -3.0, the query is identified as irrelevant (e.g., general trivia or coding) and an instant refusal message is returned immediately without invoking the LLM.
Q5: What is the Tri-State Completeness Principle in completeness_validator.py?
Answer: In travel and accessibility, missing data must never be reported as confirmed absence. The validator distinguishes between: (1) Confirmed Available, (2) Confirmed Unavailable (explicit negative statements like "No lift"), and (3) Information Not Available (missing data), avoiding misleading claims.
